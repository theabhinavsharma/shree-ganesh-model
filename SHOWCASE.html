The Architecture

5 ML engines — consensus voters, honestly accounted

What each engine contributes TODAY: all five vote into a top-30 consensus that creates rare Tier-1 picks (it has fired once in the live record — HESTERBIO/ORIENTHOT, both hit target). The multibagger engine additionally provides the regime gate; its original 2x-in-180-days TARGETS are retired to the Archive — that was the origin-story goal, not the shipped product. A weekly shadow A/B (logs/lean_shadow.jsonl) publishes whether the engine layer changed the basket at all — the week it first did, both consensus picks won.

A name only ships if it appears in ≥2 engines' top-15 AND survives contamination QC AND operator-pump detection AND RSI < 80 filter. Most names die in the cascade.

# How the cross-engine vote works
def is_actionable(symbol):
    in_engines = sum(symbol in top_15(e) for e in ENGINES)  # count of top-15 hits
    if in_engines < 2:                  return False         # need cross-validation
    if contaminated(symbol):            return False         # unrecorded -30%+ drop
    if operator_pump(symbol):           return False         # 3+ consecutive UCs
    if rsi(symbol) > 80:                return False         # chase zone
    if adv_cr(symbol) < 2.0:            return False         # illiquid
    if score_5pct_15d(symbol) < 0.55:   return False         # below floor
    return True

📌 THE OUTPUT CONTRACT — read this before you build anything

This repo contains TWO generations of system and several diagnostic layers. If you rebuild from this page, the ONE production output you must reproduce is:

Everything else — find_achievable_frontier.py (frontier grid), scorers with a ≥0.90 calibrated bar, the multibagger and 180d engines — are upstream engines and diagnostics, NOT the tradeable output. A known failure mode: copiers rebuild the older "frontier picks" layer (touch-probability, score ≥0.90, -7% stop) and get completely different picks — that layer answers "will the intraday high TOUCH +X%?" (a 58% base-rate question), not "what does the trade earn under the C2 exit contract?". If your rebuild's daily output is a frontier_picks_*.md, you built the deprecated diagnostic (see Archive).

Convergence check: run verify_freshness.py (must exit 0), then re-emit on the same data_through date as a committed basket and diff — same data must reproduce the same 8 names, ranks, scores and per-pick vol-scaled SLs (as_of_date and input mtimes naturally differ; we verify the picks/scores reproduce exactly, live; LightGBM random_state=42; universe ADV ≥ ₹5cr AND close > ₹50).

The trade spec (C2 contract — locked 2026-08-18 by tournament, see table below)

# One basket per week. 8 names, equal weight, 100% deployed. Plus 2 ranked RESERVES.
TARGET      = +5% touch     # book HALF, trail the rest at +2.5% from entry
STOP_LOSS   = vol-scaled    # per pick: 3 × the stock's OWN 20d daily vol,
                            # floor -3%, cap -12% (emitted as sl_pct / sl_3pct)
TIMEOUT     = 15 trading days   # exit whatever remains at market
NAMES       = 8 × 12.5% + reserves R1/R2 at 0% (see entry rules)
REFRESH     = weekly — scan often, NEVER churn holdings (returns are back-loaded:
              only 45% of eventual +5% touches happen by day 5)

# Levels (generate_hybrid_basket.py _pick):
BUY_ZONE    = close × [0.99, 1.01]
TARGET_PX   = close × 1.05
SL_PX       = close × (1 + sl_pct)   # per-pick, printed in the basket JSON

# ENTRY PROTOCOL (learned the hard way — picks gapped +4.8% before we could buy):
#  1. Weekend AMO limit orders at buy_high → they enter NSE's 9:00-9:07 pre-open
#     auction and fill AT THE AUCTION PRICE if it opens inside your limit.
#  2. A pick opening above buy_high is NEVER chased — its +5% is spent in the gap.
#  3. Gapped pick's 12.5% → highest-ranked RESERVE that IS inside its zone, else cash.

# EVERY pick ships RANKED by confidence with a plain-language rationale —
# the generator hard-asserts this; an unranked basket cannot emit.
# confidence = min(engines,3)×1.5 + band_fit + honest-zone-ML proximity×2 + cs×0.5
# (band_fit is a 0-3 legacy score still computed on ABSOLUTE bands — kept as a
#  ranking ingredient under live probation via the weekly RANK CHECK)
# Live validation ("RANK CHECK", printed weekly): ranks 1-4 touch 75% vs ranks 5-8 50%.

Why these exit rules — the A/B/C tournament (4,222 trades, day-by-day, entry next-open, 0.30% costs)

Exit contractNet/tradeMedianCAGRMax drawdown
A: hold 15d, no stop, no target+0.985%-0.64% ⚠️+20.9%-58.5%
B: half @+5%, rest to day-15, no stop+0.493%+1.65%+12.5%-48.6%
C1: flat -3% SL (our old rule)-0.074%-3.30%+1.8%-27.2%
C2: vol-scaled SL + half @+5% + trail (SHIPPED)+0.220%+3.45%+11.6%-18.6%

A has the best mean but a negative median and a ruinous drawdown — a lottery portfolio you'd abandon at the bottom. C2 keeps ~all of B's return at a third of the drawdown, with the only strongly positive median. The old flat -3% SL is dead: day-by-day it fired on 63.5% of trades (a 3% stop is inside ordinary small-cap noise) and went negative after costs. Full history of how we got here: see the Archive at the bottom.

The selection filter — every stock judged on its own scale (z-bands, shipped 2026-08-25)

Absolute thresholds (RSI 42–60 for everyone) treat a sleepy pharma and a high-beta smallcap identically. We replaced them with each stock's own distribution — same rule, per-stock calibration. Shipped after a pre-registered A/B: pool touch rate 55.9% vs 54.1% (10-yr) and 60.1% vs 55.7% (since April); the names z-bands add that absolute bands missed were the best bucket in the test (60–69% touch).

# QC filter (apply_qc_filter, generate_hybrid_basket.py)
rsi_z         in [-1.0, +0.25]   # RSI vs the stock's OWN 252d mean/std: neutral-to-washed
ret20d_z      in [-1.0, +0.75]   # 20d move in units of the stock's OWN vol (×√20)
ret5d_z       in [-1.0, +1.0]    # no own-scale parabolic
volume_vs_20d < 2                # no distribution days
close > ₹50 · adv_20d ≥ ₹5cr     # no pennies, real exit liquidity
max_uc_streak < 2                # operator-pump kill (UC day = +4.98–10.05%, trailing 45 cal-days)
contamination = NONE             # no -30% single-day drop lacking a corp-action within ±5d

# ML layer: LightGBM classifier (rolling train/test windows, retrained weekly).
# Only the HONEST zone is trusted: picks need ml_score in [0.50, 0.75].
# The classifier's MOST confident band (≥0.85) historically UNDERPERFORMED —
# high raw scores get less credit, not more.
# Tier-1 = 2+ engine consensus (rare, strongest signal) · Tier-2 = ML + bands. Always 8 + 2 reserves.

Tape forensics — every pick interrogated before entry, automatically

Born when a user eyeballed one sinking pick and asked "why aren't we looking closely at everything?" Now a pipeline step (tape_forensics.py): every pick and reserve is scanned for distribution days (≤-3% on >1.5× volume = institutional selling), post-results dumps on high volume (informed selling we can't read), broken structure, and delivery quality — graded severity 0–3. Severity-3 names become swap candidates — an analyst panel + adversarial consistency check recommends, a human confirms (the scan itself never auto-trades). Low-volume dips are drift, not distribution — volume separates noise from information. Mid-trade monitoring rule (currently manual, backtested to improve the worst trade from -56% to -48%): a holding printing a fresh distribution day is exited next open.

The weekly learning loop — the system scores itself before it picks again

  • 📊 Self-scoring first: score_basket_outcomes.py replays every past basket day-by-day under the published rules and prints two numbers before any new pick: the goal tracker (share of picks touching +5% — the target is 90%, we're at ~42-62%) and the RANK CHECK (do ranks 1-4 beat 5-8? currently 75% vs 50% — the day that flips, the ranking weights get rebuilt).
  • 🔁 Miss diagnosis + retrain: miss_learner.py buckets last window's missed winners (universe / model / threshold / caught / correctly-filtered); the classifier retrains weekly on rolling windows (its dates used to be frozen — mistake #13).
  • ⚖️ Nothing ships on a hunch: every filter/model change must beat the incumbent on a full walk-forward (13+ weekly windows minimum). Two features and one "obviously good" sub-cohort died at this bar — all in the ledger.
  • ⏳ Scan weekly, never churn holdings: refresh-frequency test showed re-picking every 3-5 days is net-negative (-10%/yr) — a trade's returns are back-loaded (only 45% of eventual +5% touches happen by day 5). Positions leave only via target, stop, day-15, or the (manual) distribution-day eviction rule.
  • 📰 "Spurt in Volume" trap: NSE taggers mislabel exchange surveillance notices as order wins. Only "Bagging/Receiving of orders/contracts" is real. Treat volume-spurt notices as attention flags, never business catalysts.
  • 🧪 Rationale is adversarially verified: every per-pick rationale is fact-checked by an independent skeptic agent against the raw data before publication (typical run: 3 numeric errors caught pre-ship). Give the verifier every source the analyst had, or it flags true numbers as fabricated.
  • 📉 32 trades is an anecdote, not a backtest. Minimum bar: full market cycle, thousands of trades, day-by-day exit simulation, entry at next-day open, ≥0.30% costs. Window-level shortcuts once inflated our CAGR by ~36 points (see Archive).
The Guardrail

The freshness gate — born from our worst incident

On 2026-07-01 we emitted a basket built on macro data 55 days stale — and reported it with a green tick. Yahoo Finance silently returned HTTP 429, the fetcher wrote nothing, the panel forward-filled old values, and every check passed because the file's dates looked fresh while its columns were rotten. If you copy one non-obvious thing from this page, copy this.

# The bug class: file-level freshness LIES.
# macro_panel.parquet: trade_date max = 2026-06-30  ✓ "fresh"
# but dxy/brent/us_10y last NON-NULL value = 2026-05-07  ✗ 55 days stale (forward-filled)

# The fix: THREE kinds of check, verified before ANY basket can emit — 27 total
FILE-LEVEL  : max(date_col) or mtime vs business-day limit      # 12 contracts
COLUMN-LEVEL: last NON-NULL date per critical column vs limit   # 14 contracts
CONTINUITY  : no run of ≥3 consecutive missing trading days     # 1 check — a fresh
                                                                # max-date can hide interior holes (we shipped a 9-session gap once)

# Contracts (verify_freshness.py) — limits in business days
PRICES        3bd   cols: close, rsi_14_daily, return_20d, volume_vs_20d + continuity
5 ENGINES     3bd   (mtime — incl. the multi_horizon CSV, once silently ungated)
ML_CLASSIFIER 3bd
MACRO_PANEL   3bd   cols: usdinr 3bd · brent/wti/us_10y/dxy/us_vix/spx 5bd each
INDUSTRY      3bd   cols: sector_5d_ret, sector_20d_ret, rs_20d
NEWS_EVENTS   5bd
ANNOUNCEMENTS 10bd
CORP_ACTIONS  10bd  # added after a 113-day silent rot: 21 missing splits/bonuses
                    # (TRENT, LICI, CUB…) were corrupting price adjustment itself

# Enforcement — NO bypass path:
generate_hybrid_basket.py  → verify_or_die() on entry; refuses to emit if ANY check fails
run_weekly_pipeline.sh     → hard-fails the whole run (exit 1)
emit_freshness_status.py   → reports/freshness_status.md dashboard, every run
# Hard-won sourcing rules (each cost us a real incident):
# 1. FRED fallback for Yahoo 429s: ^TNX→DGS10 · DX-Y.NYB→DTWEXBGS · ^VIX→VIXCLS · ^GSPC→SP500.
#    Daily brent/wti come from FRED directly (DCOILBRENTEU/DCOILWTICO), never Yahoo.
# 2. Use an HONEST bot User-Agent ("ZoomFetcher"). FRED's WAF tarpits spoofed-Chrome UAs
#    (connection accepted, never answered → 6-minute timeouts). Honest UA: 200 in 0.3s.
# 3. Price refresh backfills ADAPTIVELY from the parquet's real max date — a fixed
#    5-day lookback once left a silent 9-session hole that fed the models garbage.
# 4. A fetcher that fails silently is worse than one that crashes loudly:
#    exit non-zero on total failure so the gate catches it downstream.

The Binding Rules

The constitution that keeps us honest

Anthropic-grade structured prompts and binding operating rules. Every commit, trade, and live prediction passes these gates. Not aspirational — actually enforced in code and pytest.

  • §1.1 — Honesty about uncertainty
    A claim of "85% hit rate" must cite a parquet path, year range, sample size, or it doesn't ship. In-sample and prospective are never confused.
  • §1.2 — Pre-commit to falsification
    Every new claim runs through devils_advocate.py BEFORE shipping. When new evidence contradicts a prior claim, lead with the contradiction. Never smooth over.
  • §1.3 — Strict walk-forward
    Train ≤ year_X-1. Calibrate on year_X-1 only. Test on year_X. Calibrators never fit on test data, even if the metric "looks better" the other way.
  • §1.4 — Multiple-testing discipline
    If N hypotheses tested, significance bar is α/N (Bonferroni). "Best of N" reporting is forbidden. Report median, range, and count tested.
  • §1.5 — Survive first, win second
    The -30% annualised drawdown floor is sacred. When the discipline cascade returns 0 fire-day signals, the answer is cash. Never force a trade to look productive.
  • §1.6 — Living calibration ledger
    Every mistake corrected goes into logs/calibration_corrections.jsonl with date, claim, correction, and the parquet path that exposed it. Past mistakes are not repeated.
  • §1.7 — Reproducibility = publishability
    A claim that cannot be reproduced from a fresh clone + the daily pipeline is not publishable, no matter how strong the number.

8 steps to your own calibrated AI trading system

Everything you need to replicate. No magic, just discipline.

01

Clone the repo

Start with the working scaffolding. All scripts, prompts, agents, tests included.

git clone https://github.com/theabhinavsharma/shree-ganesh-model.git
cd shree-ganesh-model
02

Set up your data fetchers

NSE bhavcopy + corporate actions + news. The repo includes ~16 fetchers in src/agentic/fetch_*.py.

python3 src/agentic/refresh_prices.py      # NSE bhavcopy, 15-year history
python3 src/agentic/build_news_event_features.py  # Corporate filings
python3 src/agentic/build_macro_panel.py   # Macro + sector context
03

Write the constitution FIRST (most important step)

Before any model. Bind yourself to honesty, walk-forward, Bonferroni, calibration ledger. Without rules, the AI will tell you what you want to hear.

cp CONSTITUTION.md ./   # use ours as a template
# Edit to your context. The 7 binding principles stay.
04

Build the 5-engine ML stack

Each engine has a different question: 180d frontier, short horizon (5%/15d, 10%/30d), 7d/15d/30d high conviction, multibagger (50%/75%/100% in 180d), multi-horizon (1d/7d/21d).

python3 src/agentic/find_180d_frontier_honest.py    &
python3 src/agentic/find_high_conviction.py         &
python3 src/agentic/find_multibagger_today.py       &
python3 src/agentic/run_multi_horizon.py            &
python3 src/agentic/compare_short_horizons.py       &
wait   # all 5 run in parallel
05

Run agents in parallel: devil's advocate + debugger + per-name DD

Spawn specialised Claude agents. Each gets one job. Cross-validate by composition.

python3 src/agentic/devils_advocate.py            # 10-vector audit
python3 src/agentic/run_agent.py debugger ...     # sanity checks
python3 src/agentic/run_agent.py trade_reviewer ...  # per-name DD
06

Apply contamination + operator-pump QC

Drop any name with unrecorded -30%+ drops or 3+ consecutive upper-circuit days. This step prevents 80% of bad trades.

# Pseudocode of the QC
for sym in candidates:
    if has_unrecorded_big_drop(sym):     drop("contamination")
    if max_consecutive_uc(sym, 30) >= 3: drop("operator_pump")
    if rsi(sym) > 80:                    drop("chase")
    if adv_cr(sym) < 2:                  drop("illiquid")
    if close(sym) < 30:                  drop("penny")
07

Commit a timestamped forward-record artifact

Every basket → live_predictions/YYYY-MM-DD.json → git commit. Immutable. This is the publishability case.

python3 emit_forward_record.py > live_predictions/$(date +%Y-%m-%d).json
git add live_predictions/ && git commit -m "Daily forward record"
git push origin main
08

Log every mistake. Religiously.

Calibration corrections ledger is the credibility moat. Document every overfit caught, every leak quarantined, every name killed by QC.

# logs/calibration_corrections.jsonl
{"ts":"2026-06-08","claim":"...","what_was_wrong":"...","correction":"...","lesson":"..."}

📉 The flat -3% stop-loss era (retired 2026-08-18)

Original spec: +5% target · flat -3% SL · book half / trail +2.5%. The coarse (window-level) backtest credited it +1.77%/trade and ≈34.6% CAGR. Day-by-day resequencing showed the -3% stop fired on 63.5% of trades (inside ordinary small-cap noise) and the geometry was -1.3% CAGR after costs (arithmetic per-cycle method; the later tournament’s geometric method scored the same rule +1.8% — both far below every alternative, and both reported here for method honesty). It also stopped out an entire live basket in two sessions (Jul-7 cohort, -3.00%), including a name that then rallied +12.8%. Replaced by the C2 vol-scaled contract after the A/B/C tournament. Intermediate findings from that review: SL -5% → +2.1% CAGR · SL -7% → +2.7% · no-SL half-trail → +8.3% (worst trade -56%).

📊 The absolute entry bands & band-fit hit-rate tables (retired 2026-08-25)

Original QC: RSI 42-60 · 20d return -10..+15% · 5d ±5% (absolute thresholds for every stock). The celebrated band table — 20d [-5,0] = 27.5% hit vs 20-30% = 19.5%; RSI 45-55 = 25.5%; "consolidation beats momentum" — did not survive the corrected-data re-check when measured by touch rate: the spreads were an artifact of the flat-bracket exit geometry (volatile names whipsawed the ±3/5% bracket; quiet names didn't — the bands were measuring volatility, not edge). Replaced by z-score bands (each stock vs its own 252-day distribution), which passed a pre-registered A/B. The band_fit ranking ingredient survives under live probation via the weekly RANK CHECK.

🔮 The frontier / touch-probability layer (deprecated diagnostic)

achievable_frontier-era claims: "98.3% hit at score ≥0.95 (5d/5%)", "97.9% (15d/5%)", "180d/+15% ~85% prospective", "9-yr dynamic-gated +8% median ROI". These measured whether the intraday high TOUCHES a level (58% base rate makes high bands cheap), not exit-rule P&L, and used a different universe cut (ADV ≥ ₹1cr). Copiers who rebuild this layer get different picks — it is a diagnostic, never the product. The production output is only live_predictions/YYYY-MM-DD_15d5pct.json.
